# ناظِم — منظم المهام ومواعيد الأسبوع 📅

تطبيق أندرويد عربي (RTL) لتنظيم حياتك: **مواعيد أسبوعية متكررة** بتذكيرات، مهام يومية، روتين ثابت، وإحصائيات التزام — بهوية ملكية داكنة (كحلي `#1A237E` + فضي + ذهبي) وخط Cairo.

## الميزات

| التبويب | ماذا يفعل |
|---|---|
| **اليوم** | تاريخ اليوم + نسبة إنجاز + بطاقة «موعدك القادم بعد كذا» + مواعيد اليوم + الروتين + المهام |
| **الأسبوع** ⭐ | اختر أي يوم من السبت للجمعة وأضف مواعيده (من — إلى) بتذكير اختياري؛ تتكرر كل أسبوع تلقائيًا وتُعدَّل في أي وقت + نسخ موعد ليوم آخر |
| **الإحصائيات** | سلسلة الالتزام، أعمدة إنجاز آخر 7 أيام، دونات توزيع المهام حسب التصنيف، ساعات المواعيد |
| **الإعدادات** | داكن/فاتح، تشغيل التذكيرات، صلاحيات الإشعارات، تصدير/استيراد نسخة JSON، مسح البيانات |

التذكيرات تعمل بنظام أندرويد نفسه (حتى لو التطبيق مقفول): «لديك موعد «زيارة الأهل» بعد نصف ساعة — 5:00 م — 7:00 م». البيانات محلية بالكامل (خصوصية 100% + يعمل بدون إنترنت).

## البناء من الموبايل فقط (بدون كمبيوتر) — عبر GitHub Actions

المستودع جاهز بكل شيء، والبناء يحصل في السحابة مجانًا:

### 1) أنشئ مستودعًا جديدًا
- من متصفح الموبايل: [github.com/new](https://github.com/new)
- اسم المستودع: `nathim` مثلاً — اجعله **Public** — اضغط **Create repository**

### 2) ارفع ملفات المشروع كاملة
1. فك ضغط `nathim_app.zip` على الموبايل (تطبيق «Files by Google» يفك الضغط بضغطة).
2. من صفحة المستودع الفارغ: **uploading an existing file** (أو Add file ← Upload files).
3. ارفع **كل المجلدات والملفات**: `lib/` و `android/` و `assets/` و `.github/` و `test/` و `pubspec.yaml` و `pubspec.lock` و `README.md` و `.gitignore` و `analysis_options.yaml` و `.metadata`.
4. ⚠️ **مهم جدًا**: مجلد `.github` يبدأ بنقطة وقد لا يظهر في بعض برامج الملفات — تأكد أنه اترفع (لازم يكون فيه `.github/workflows/build.yml` وهذا هو ملف البناء التلقائي).
5. اضغط **Commit changes**.

> نصيحة: لو متصفحك ما يقبلش رفع مجلدات كاملة، فعّل «موقع سطح المكتب» (Desktop site) من قائمة المتصفح ثم أعد المحاولة — قائمة اختيار الملفات تصبح أقوى.

### 3) البناء التلقائي
- بمجرد الرفع، يبدأ البناء تلقائيًا: افتح تبويب **Actions** في المستودع وشاهد التقدم (يستغرق 6–10 دقائق أول مرة).
- عند نجاح البناء (علامة ✓ خضراء): افتح صفحة **Releases** ← آخر إصدار ← حمّل `app-release.apk` من قسم **Assets**.

### 4) ثبّت التطبيق
- افتح ملف APK من الإشعارات.
- لو سألك الهاتف: اسمح بـ «التثبيت من مصادر غير معروفة» لهذا المتصفح.
- بعد أول فتح: وافق على صلاحية الإشعارات (وزر «التحقق من الصلاحيات» موجود في الإعدادات).

## الإصدارات — لماذا هذه بالتحديد؟ (قراءة مهمة)

هذه الإصدارات **مُثبتة ومختبرة معًا**: كود المشروع اجتاز `flutter analyze` بلا أي مشكلة على Flutter 3.35.3، ومصفوفة الحزم اتحلّت بنجاح عبر `pub get` حقيقي (انظر `pubspec.lock` المرفق).

| المكوّن | الإصدار | السبب |
|---|---|---|
| **Flutter (CI)** | `3.35.3` مثبت في `build.yml` | تثبيت الإصدار يمنع انكسار البناء مستقبلًا عند خروج إصدارات جديدة — نفس إصدار توليد ملفات `android/` المرفقة |
| Dart SDK | `>=3.3.0 <4.0.0` | نطاق مريح يعمل على Flutter 3.27+ حتى 3.35+ |
| `intl` | `any` | ⭐ **درس مشكلة الإصدارات الشهيرة**: `flutter_localizations` يربط intl بإصدار محدد من SDK نفسه (0.20.2 في 3.35)؛ تحديد رقم يدوي مثل `^0.19.0` يسبب تعارض حل الإصدارات. كتابة `any` تجعل SDK هو المتحكم = صفر تعارضات |
| `flutter_local_notifications` | `^18.0.1` | يدعم Flutter 3.22+، وواجهته (zonedSchedule + matchDateTimeComponents للتكرار الأسبوعي) مستقرة |
| `timezone` | `>=0.9.4 <0.11.0` | نطاق واسع يوافق ما تطلبه flutter_local_notifications دون تعارض |
| `flutter_timezone` | `^3.0.1` | v3 تعيد `String` بسيطًا؛ v4 غيّرت الواجهة — حدّدنا السقف عند <4 |
| `share_plus` | `^10.0.2` | محلولة فعليًا 10.1.4 — تعمل مع 3.24+ |
| `provider` / `shared_preferences` | `^6.1.2` / `^2.2.3` | نطاقات واسعة مجربة |
| Java (CI) | `temurin 17` | Gradle 8.12 مع Java 21 فيه خلل تحويلات معروف — Java 17 هو الأثبت |
| Gradle/AGP/Kotlin | من قالب Flutter 3.35.3 | ملفات `android/` مرفقة كما ولّدها نفس الإصدار |

> **لو ظهرت لك مشكلة إصدارات مستقبلًا**: غيّر رقم `flutter-version` في `.github/workflows/build.yml` فقط، ثم ارفع تعديلًا جديدًا — الـ Actions سيعيد البناء. لا تغيّر أرقام الحزم يدويًا إلا عند الحاجة؛ `pubspec.lock` المرفق يثبت ما يعمل الآن.

## استكشاف الأخطاء

| المشكلة | الحل |
|---|---|
| Actions لا تعمل أصلًا | تأكد أن `.github/workflows/build.yml` اترفع فعلًا بالمسار الصحيح |
| فشل البناء | افتح الـ run الفاشل ← اضغط على خطوة **build apk** واقرأ أول خطأ أحمر، وصلّني بلقطة |
| فشل `flutter create` في CI | عادة تعارض اسم — تأكد أن `pubspec.yaml` فيه `name: nathim` كما هو |
| الإشعارات لا تصل | إعدادات الهاتف ← التطبيقات ← ناظِم ← فعّل الإشعارات + اسمح بالعمل في الخلفية (بعض شركات البطاريات تقتلها) |
| تريد إعادة البناء يدويًا | تبويب Actions ← اختر «بناء التطبيق (APK)» ← **Run workflow** |

## النسخ الاحتياطي
